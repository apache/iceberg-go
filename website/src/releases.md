# Releases

Apache Iceberg Go follows the standard Apache release process. Releases are cut from `main`, voted on by the Apache Iceberg PMC, and published as signed source tarballs to `https://downloads.apache.org/iceberg/` and as Go module versions tagged `vX.Y.Z`.

## Latest release

- [Latest release on GitHub](https://github.com/apache/iceberg-go/releases/latest)
- All releases: [github.com/apache/iceberg-go/releases](https://github.com/apache/iceberg-go/releases)

## Using a release

Pin a tagged version directly with Go modules:

```sh
go get github.com/apache/iceberg-go@vX.Y.Z
```

To track `main`, use `@main` instead of a version tag.

## Release notes

Per-release notes (highlights, breaking changes, contributors) are published on the [GitHub Releases page](https://github.com/apache/iceberg-go/releases). Iceberg Go does not maintain a curated `CHANGELOG.md` in the repository; the GitHub Releases page is the canonical source.

### Unreleased compatibility notes

- **SigV4 keeps the token or credential as `Original-Authorization`.** With `rest.sigv4-enabled=true` (or `rest.auth.type=sigv4`) and a `token` or `credential`, requests used to be signed with the token silently dropped, because the SigV4 signature replaced the `Authorization` header. They now carry it as `Original-Authorization`, included in the signed headers, as Iceberg Java does. A server behind SigV4 that ignores the header is unaffected.
- **Float and double literal comparators use Iceberg ordering.** `TypedLiteral.Comparator()` now orders `-0.0` before `+0.0` and NaN after all other values; NaN compares equal to NaN. Callers that use these public comparators may see a different order or equality result.
- **Table creation rejects duplicate field IDs.** `NewMetadata`, and `CreateTable` on catalogs that build metadata through it (not REST), now return `ErrInvalidSchema` when two fields in the schema share an ID, including unset `0` or `-1` IDs, even for unpartitioned, unsorted tables. Before, the partition spec or sort order could bind to the wrong column. Callers should assign unique IDs (or let the schema be built with fresh IDs). This matches Java, whose `Schema` constructor rejects duplicate IDs.
- **Sort order replacements reuse orders staged earlier in the same transaction.** If a transaction replaces order A with B and then returns to A, A becomes the default again instead of B. The final update reuses A's ID instead of adding another definition. Reuse of orders from earlier commits was already supported.
- **Case-insensitive field binding rejects only ambiguous names.** `Reference.Bind` and `Schema.Select` return `ErrInvalidSchema` when the requested case-insensitive name matches different field IDs, and the error includes both names. Unrelated names remain available to scans, writes, and schema, partition, and sort order updates.
- **Delete files now have a separate 64 MiB target.** Equality-delete and v2 position-delete files previously used `write.target-file-size-bytes` (512 MiB by default, or the table's override) as their file-size target. They now use `write.delete.target-file-size-bytes`, which defaults to 64 MiB. After upgrading, tables may produce more, smaller delete files unless this new property is set. To preserve the previous delete-file size target, set `write.delete.target-file-size-bytes` to the table's former effective `write.target-file-size-bytes` value (`536870912` when the data-file target was unset). The data-file target itself is unchanged.
- **Schema reads now reject invalid identifier fields.** Table and view metadata with `identifier-field-ids` referring to an optional, float/double, missing, non-primitive, or improperly nested field now fails to load with `invalid schema` (for example, `invalid schema: identifier field "foo" must be required` or `invalid schema: identifier field "foo" cannot be float or double`). Older iceberg-go releases could load such metadata, but Java Iceberg already rejects it. To recover an affected table, back up its metadata and use an atomic catalog metadata repair to remove the invalid identifier IDs or replace them with IDs of existing, required, non-floating primitive fields nested only in required structs. Do not edit the currently referenced metadata file in place. Repeated identifier IDs are deduplicated on read.

- **Schema JSON defaults preserve integer precision.** `long` defaults now decode as `int64` instead of `float64`; non-integral, non-numeric, or out-of-range values now fail to parse. Numeric literals inside object and list defaults decode as `json.Number` rather than `float64`.

- **`StructType.Fields()` returns a copy.** Changing the returned slice no longer changes the struct, matching `ListType.Fields()` and `MapType.Fields()`. Build a new type with `NewStructType` instead. `NumFields()` and `Field(i)` read fields without copying, and `NewListType` and `NewMapType` are the constructors for the other nested types. The exported fields are unchanged for now; they become unexported before v1.0.0 (see [#2062](https://github.com/apache/iceberg-go/issues/2062)).
- **`io.StatIO.Stat` accepts a context.** The method now takes a `context.Context` before the path, so custom `StatIO` implementations and callers must pass the operation context.
- **Commits retry conflicts by default.** `commit.retry.num-retries` now defaults to `4`, as in Java and PyIceberg, so `Commit` refreshes and replays a conflicting commit up to four times before returning `ErrCommitFailed`. Set it to `0` to keep failing on the first conflict. `table.CommitNumRetriesDefault` changes from `0` to `4`.
- **Schemas store binary and fixed defaults as hex strings.** `NewSchema`, `NewSchemaWithIdentifiers` and `UpdateSchema.AddColumn` (through `Apply()`) convert `[]byte`, `BinaryLiteral` and `FixedLiteral` defaults of binary and fixed fields, including fields nested in structs, lists and maps, to the lowercase hex string iceberg-go writes to metadata JSON, so a field read back from a schema holds a `string` such as `"0aff"`. Code that type-asserts these defaults to `[]byte` must decode the string instead, for example with `hex.DecodeString`. A schema built in process now equals the same schema read from metadata with lowercase hex. `Equals` compares the strings case-sensitively, and Java writes uppercase hex (see [apache/iceberg#18352](https://github.com/apache/iceberg/issues/18352)). The fields and types passed in are not modified.
- **Predicates reject NaN literals when bound.** `EqualTo`, `NotEqualTo`, `LessThan`, `LessThanEqual`, `GreaterThan`, `GreaterThanEqual`, `IsIn`, `NotIn` and `LiteralPredicate`/`SetPredicate` with a NaN float literal now fail in `Bind` with `ErrInvalidArgument`, as Java does. That includes the string `"NaN"` on a float column and a NaN on a decimal column, which used to bind as zero. Scans, `ExpressionEvaluator` and the metrics evaluators all bind first, so they return the error too. Use `IsNaN` and `NotNaN` to match NaN values.
- **SQL view APIs align with `catalog.ViewCatalog`.** `CreateView` now takes a `*view.Version`, schema and options, and returns `*view.View`. `LoadView` now returns `*view.View`; use `Metadata()` to access its metadata. If the caller leaves `DefaultCatalog` empty, SQL still sets it to the catalog name.
- **`LocationProvider.NewDataLocation` takes the partition path.** The method is now `NewDataLocation(dataFileName, partitionPath string)`, matching Iceberg Java and PyIceberg, so custom `LocationProvider` implementations must add the argument. Callers pass the partition path there, or `""` for an unpartitioned file, instead of prefixing the file name.
- **Partitioned data files follow the table's location provider.** With `write.object-storage.enabled=true` and the default `write.object-storage.partitioned-paths=true`, new partitioned files land under `data/<hash>/<partition>/` instead of `data/<partition>/<hash>/`, which can affect prefix-based lifecycle rules and bucket policies. `write.object-storage.partitioned-paths=false` and `write.data.path` now apply to partitioned writes. Partitioned paths also no longer percent-encode the table location: `s3://bucket/my table` stays literal instead of becoming `my%20table`, as for unpartitioned writes. Existing files stay where they are.
- **External object-store data paths include table context.** For object-storage tables whose `write.data.path` is outside the table location, new data files now use `<hash>/<db>/<table>/...` after the shared storage prefix. This applies whether `write.object-storage.partitioned-paths` is `true` or `false`. The new prefixes may affect prefix-based lifecycle rules and bucket policies. Existing data files do not move.
- **Catalog capabilities split into narrower interfaces.** `catalog.Catalog` now embeds `TableCatalog` and `NamespaceCatalog` with unchanged table and namespace methods. `Name() string` is now required, breaking third-party catalogs and test fakes. `ViewCatalog` is optional (REST, Hive, and SQL), while REST also implements `UpdatableViewCatalog` for `UpdateView`. REST and SQL implement `RenamableViewCatalog` for `RenameView`. Use `catalog.As[T](cat)` and the `Unwrap() Catalog` convention to discover optional capabilities through decorators. Future capabilities should use optional interfaces rather than extending `Catalog`.
- **Rename IO methods take a context.** `RenameIO.Rename` and `RenameNoReplaceIO.RenameNoReplace` now take `context.Context` first, so custom implementations and callers must update.
- **`ReplaceFilesWithDeleteFiles` removed.** For delete-file replacements, use `tx.NewRewrite(snapshotProps)`, call `DeleteFile` for each source file and `AddDeleteFileWithDataSequenceNumber` for each replacement, then commit the builder. Rewrites record a `replace` snapshot instead of `overwrite`. The five-argument `ReplaceFiles` API is unchanged and remains available for compaction and delete-file removals.
- **Manifest and deletion-vector reads take a context.** `Snapshot.Manifests`, `ManifestFile.Entries`, `iceberg.EntriesWithProjection`, `dv.ReadDV` and `dv.ReadDVs` now take a `context.Context` first argument and pass it to `IO.Open`. Custom `ManifestFile` implementations must add it to `Entries`.
- **Path-based data-file addition renamed.** Replace `Transaction.AddFiles` with `AddDataFilesByPath`, `AddFilesOption` with `AddDataFilesByPathOption`, and `WithAddFilesConcurrency` with `WithAddDataFilesByPathConcurrency`. Behavior is unchanged.
- **Manifest builder constructor renamed.** Replace `iceberg.NewManifestFile(...)` with `iceberg.NewManifestBuilder(...)`. It still returns a `ManifestBuilder`.
- **Manifest sequence APIs use explicit names.** `ManifestBuilder.SequenceNum` and `ManifestFile.SequenceNum` become `SequenceNumber`, and `ManifestFile.MinSequenceNum` becomes `MinSequenceNumber`. `ManifestEntryBuilder.SequenceNum` and `ManifestEntry.SequenceNum` become `DataSequenceNumber`. `FileSequenceNum` becomes `FileSequenceNumber` for entries and their builder. Avro and JSON field names are unchanged.
- **`io.ReadFileIO.ReadFile` accepts a context.** The method now takes a `context.Context` before the path, so custom `ReadFileIO` implementations and callers must pass the operation context.
- **View and UDF metadata builder constructors are infallible.** `view.NewMetadataBuilder` and `udf.NewMetadataBuilder` now return only a builder instead of `(builder, error)`; remove error handling at call sites.
- **Table metadata getter renamed.** Replace `table.Metadata.Version()` with `table.Metadata.FormatVersion()`, consistent with Iceberg Java and Go view/UDF metadata. Metadata JSON is unchanged.
- **Snapshot ref type field renamed.** Replace `table.SnapshotRef.SnapshotRefType` with `table.SnapshotRef.Type`. The JSON field is still `"type"`.
- **As-of snapshot lookups now use inclusive timestamps.** Replace `tbl.SnapshotAsOf(timestampMs, true)` with `tbl.SnapshotAsOf(timestampMs)`. The method always selects the latest snapshot at or before the timestamp, matching Java Iceberg's `SnapshotUtil.nullableSnapshotIdAsOfTime`. For strict-before lookup, use `SnapshotLogEntryAsOf(tbl.Metadata().SnapshotLogs(), timestampMs, false)`.
- **Snapshot timestamp property key corrected.** `PropertyCurrentSnapshotTimestamp` now uses `current-snapshot-timestamp-ms`. The old `current-snapshot-timestamp` spelling is no longer reserved and remains usable as a custom property.
- **FileIO open and remove take a context.** `io.IO.Open` and `io.IO.Remove` now take a `context.Context` first argument, so custom `io.IO` implementations must add it. `maintenance.WithCleanupDeleteFunc` now takes `func(context.Context, string) error`.
- **Hadoop catalog construction takes a context.** `hadoop.NewCatalog(name, warehouse, props)` becomes `hadoop.NewCatalog(ctx, name, warehouse, props)`. The context bounds filesystem setup; the catalog's filesystem keeps its values but not its cancellation.
- **Config loading reports errors.** `config.LoadConfig` now returns `([]byte, error)`, and `config.LoadConfigFile` is removed; call `LoadConfig` instead. A missing default `~/.iceberg-go.yaml` still returns no data and no error.
- **Branch transactions return initialization errors.** `Table.NewTransactionOnBranch(branch)` now returns `(*Transaction, error)`, and `Table.NewTransactionOnBranchWithError` is removed. Use `NewTransactionOnBranch` and handle its error.
- **Retries preserve staged update order.** An append staged after `RollbackToSnapshot` stays on the rollback target after a retry or resumed `Commit`. If a staged update cannot apply after refresh, the transaction ends with `table.ErrTransactionUnusable`. For example, `UpgradeFormatVersion` cannot apply if a peer has committed a higher format version. The error preserves its cause and also matches `table.ErrCommitFailed` if that cause is a conflict. Previously, for transactions without a staged expiry, these failures returned `table.ErrCommitRejected` and left the transaction resumable. A catalog rejection on the first attempt still returns `table.ErrCommitRejected` and leaves the transaction resumable.
- **Retries renew snapshot timestamps.** A retry or resumed `Commit` stamps each snapshot it replays from a staged write with the current time, at least one millisecond after its parent, as Java's `SnapshotProducer` does. A snapshot staged more than a minute before a peer's commit no longer fails the retry. The committed timestamp is the time of the attempt that lands, so an `ExpireSnapshots` staged after the write in the same transaction keeps that snapshot when the commit retries.
- **Snapshot expiration now tolerates concurrent ref changes.** If a concurrent commit moves a ref that the expiry read, a retry or later `Commit` replans instead of failing with `table.ErrCommitFailed`. The committed expiry can differ from `Transaction.StagedTable`. See [Snapshot expiration](./concurrent-writes.md#snapshot-expiration) for cases that now fail with `table.ErrTransactionUnusable`.
- **Schema JSON constructor uses the Go initialism.** Replace `iceberg.NewSchemaFromJsonFields` with `iceberg.NewSchemaFromJSONFields`.
- **AWS identifiers use the Go initialism.** `glue.AwsProperties`, `glue.WithAwsConfig` and `glue.WithAwsProperties` become `glue.AWSProperties`, `glue.WithAWSConfig` and `glue.WithAWSProperties`; `sigv4.WithAwsConfig` becomes `sigv4.WithAWSConfig`; `utils.WithAwsConfig` and `utils.GetAwsConfig` become `utils.WithAWSConfig` and `utils.GetAWSConfig`; and `config.CatalogConfig.AwsProfile` becomes `AWSProfile`. The `aws-profile` YAML key is unchanged.
- **KMS factory registration now takes a context.** Change `encryption.KMSFactory` implementations to accept `(context.Context, map[string]string)` instead of only properties, and call `encryption.LoadKeyManagementClient(ctx, props)` instead of `LoadKeyManagementClient(props)`. The existing global `RegisterKMS`, `UnregisterKMS`, and `GetRegisteredKMSNames` functions still use the default registry; `RegisterKMS` still panics for invalid registrations. Use `encryption.MustRegisterKMS` for provider initialization. For isolated registrations, create `registry := encryption.NewKMSRegistry()` after importing any KMS providers and call `registry.Register`, `registry.Load(ctx, props)`, `registry.Names`, or `registry.Unregister`. New registries snapshot the global registrations; subsequent changes do not propagate.
- **Name-mapping child lookup renamed.** Replace `MappedField.GetField(name)` with `MappedField.FindFieldByName(name)`, which returns `(*MappedField, bool)`. The new method returns a pointer to the actual child field rather than a copy, and reports a missing name with `false`.
- **Data file block size setter removed.** `iceberg.DataFileBuilder.BlockSizeInBytes` is removed. New v1 manifests use the Avro schema's 64 MiB default when the field is unset. V2/v3 omit this deprecated field, and legacy v1 values remain readable.
- **View creation APIs take a named SQL representation.** `view.NewVersionFromSQL`, `view.CreateView`, and `view.CreateViewWithIOProperties` now accept a `view.Representation{SQL: sql, Dialect: dialect}` instead of positional SQL/dialect strings. The dialect is required; Hive preserves the selected representation's dialect.
- **View SQL representation construction uses named fields.** Replace `view.NewRepresentation(sql, dialect)` with `view.NewRepresentation(view.Representation{SQL: sql, Dialect: dialect})`. Serialized JSON is unchanged.
- **Hive views keep the caller's view version.** `hive.Catalog.CreateView` now stores every representation, the summary, the default namespace and `default-catalog` as passed, instead of one representation with `default-catalog` set to `"hive"`.
- **Reserved table properties now use a read-only API.** Replace references to `table.ReservedProperties` with `table.ReservedProperties()`. The function returns a fresh slice, so callers cannot change metadata validation by modifying it.
- **Fixed and decimal constructors return errors.** `iceberg.FixedTypeOf` and `iceberg.DecimalTypeOf` now return `(type, error)` instead of panicking for invalid inputs. Use `MustFixedTypeOf` or `MustDecimalTypeOf` only for known-valid values.
- **SQL UDF representations now use struct literals.** The `udf.NewSQLRepresentation(dialect, sql)` function, available since v0.7.0, is removed. Use `udf.SQLRepresentation{Dialect: "trino", SQL: "x + 1"}` instead. Empty fields and duplicate dialects are checked during metadata validation; serialized JSON is unchanged.
- **Filesystem adapter construction consolidated.** Replace `io.FSPreProcName(fsys, fn)` with `io.FS(fsys, io.WithNamePreprocessor(fn))`. Plain `io.FS(fsys)` remains supported.
- **Table purge is required on catalogs.** The `catalog.Catalog` interface now embeds `catalog.PurgeableCatalog`; every custom catalog implementation must provide `PurgeTable(ctx, identifier) error`. The narrow `catalog.PurgeableTable` interface is renamed to `catalog.PurgeableCatalog`. Built-in purge behavior is unchanged.
- **Unify statistics blob types with Puffin.** Replace `table.BlobType` with `puffin.BlobType` when constructing `table.BlobMetadata`. Replace `table.BlobTypeApacheDatasketchesThetaV1` with `puffin.BlobTypeDataSketchesTheta` and `table.BlobTypeDeletionVectorV1` with `puffin.BlobTypeDeletionVector`. Use `puffin.BlobType.IsKnown()` to identify the types defined by the Puffin specification; the redundant `table.BlobType.IsValid()` method is removed. Unknown non-empty blob type names still round-trip through table metadata.
- **View representation field uses the Go SQL initialism.** Replace `view.Representation.Sql` with `view.Representation.SQL`. Serialized view metadata still uses the `sql` JSON field.
- **Orphan cleanup results now expose only `OrphanFiles`.** Replace `result.OrphanFileLocations` with `result.OrphanFiles` (each entry has `Path` and `SizeBytes`). `OrphanCleanupPlan.Files()` still provides path-only lists during planning.
- **Catalog identifier helper renamed.** `catalog.TableNameFromIdent` is removed. Use `catalog.ObjectNameFromIdent` for tables, views, and functions.
- **Substrait expression conversion no longer takes case sensitivity.** `substrait.ConvertExpr(schema, expression, caseSensitive)` becomes `substrait.ConvertExpr(schema, expression)`. Case sensitivity remains part of expression binding.

- **Transform formatting requires the result type and uses the Java-aligned method name.** `Transform.ToHumanStr(value)` and `Transform.ToHumanStrType(resultType, value)` are removed. Use `Transform.ToHumanString(resultType, value)` to format partition values, including timestamps with time zones.
- **Catalogs now require cleanup.** The `catalog.Catalog` interface includes `Close() error`. Custom catalog implementations must provide `Close`, and callers should close catalog instances after use. `catalog.Closer` is removed. Replace `cat.(catalog.Closer)` checks with `defer cat.Close()`; `catalog.Catalog` already implements `io.Closer`, so no type assertion is needed.

- **`table.ErrDataFilesMissing` no longer matches `table.ErrCommitFailed`.** An operation that adds delete files referencing data files that are not live, for example because a concurrent commit removed them, fails with `ErrDataFilesMissing`. The error is now terminal, like `table.ErrCommitDiverged`, matching Java's `ValidationException`, so code that retries when `errors.Is(err, table.ErrCommitFailed)` no longer retries it. When `Transaction.Commit` returns it, the error also matches `table.ErrTransactionUnusable`. Rebuild the delete against the current table instead.

- **Puffin writer property setter renamed.** `puffin.Writer.AddProperties` is now `puffin.Writer.SetProperties`. Repeated calls still merge keys; use `ClearProperties` to clear custom properties before finishing.

- **Orphan file cleanup moved to `table/maintenance`.** The orphan-cleanup and file-purge API is no longer on `table.Table`; it now lives in the `table/maintenance` package as free functions that take the table as their first argument (matching `table/compaction`). For example, `tbl.DeleteOrphanFiles(ctx, ...)` becomes `maintenance.DeleteOrphanFiles(ctx, tbl, ...)`. Because `table/maintenance` imports `table` (and not the reverse), this cannot be offered as a deprecation shim on `table.Table` without an import cycle, so callers must switch to the new package. The following moved from `table` to `table/maintenance`:
    - Functions (now free functions taking `*table.Table`): `DeleteOrphanFiles`, `PlanOrphanFiles`, `ExecuteOrphanCleanup`, `PurgeFiles`.
    - Types: `OrphanCleanupOption`, `OrphanCleanupResult`, `OrphanFile`, `OrphanCleanupPlan`, `PrefixMismatchMode`.
    - Constants: `PrefixMismatchError`, `PrefixMismatchIgnore`, `PrefixMismatchDelete`.
    - Option constructors: `WithCleanupLocation`, `WithCleanupFilesOlderThan`, `WithCleanupDryRun`, `WithCleanupDeleteFunc`, `WithCleanupMaxConcurrency`, `WithPrefixMismatchMode`, `WithEqualSchemes`, `WithEqualAuthorities`. The four generic names (`WithLocation`, `WithFilesOlderThan`, `WithDryRun`, `WithDeleteFunc`) gained the `WithCleanup` prefix for consistency.

    Relatedly, the previously unexported `isGCEnabled` is now `table.IsGCEnabled`, so the new package can gate destructive operations on the `gc.enabled` table property.
- **Data-file replacement methods renamed.** Use `ReplaceDataFilesByPath` for string paths. Use `ReplaceDataFiles` for prebuilt `DataFile` values instead of `ReplaceDataFilesWithDataFiles`.

- `maintenance.PurgeFiles` (previously `Table.PurgeFiles`) now calls `IO.Remove` concurrently, with up to 32 calls in flight, when the filesystem does not implement `BulkRemovableIO`. Custom IO implementations, including those registered with `io.Register`, must make `Remove` safe for concurrent use and synchronize any shared mutable state. The bulk deletion path is unchanged.
- **Snapshot summaries report deletion vectors separately.** On v3 tables, DVs are counted under `added-dvs` and `removed-dvs` instead of `added-position-delete-files` and `removed-position-delete-files`. `added-files-size` and `removed-files-size` use each DV's `content_size_in_bytes` instead of its whole Puffin file, so they go down for commits with DVs. `total-files-size` is updated from these values. Partition summaries, commit reports and OTel metrics change the same way. Existing snapshots are not rewritten.
- **Deletion vectors identify row positions.** New Puffin blobs list `_pos` field ID `2147483645` in `fields`, matching Iceberg Java. Existing files are unchanged.

- **Partition and sort source accessors renamed.** Replace `PartitionField.SourceID()` and `SortField.SourceID()` with `FirstSourceID()`. Their behavior and serialized fields are unchanged.

- **Row-lineage column predicate renamed.** Use `iceberg.IsRowLineageColumn` instead of `iceberg.IsMetadataColumn` to identify `_row_id` and `_last_updated_sequence_number`. Use `iceberg.IsReservedFieldID` to check the full reserved metadata field ID range.
- **File writes and directory walks now take an operation context.** Update `WriteFileIO` and `ListableIO` implementations and calls to `Create`, `WriteFile`, and `WalkDir` to pass `context.Context`; cloud writes and listings use it for cancellation.
- **In and NotIn follow SQL semantics for NULL.** A multi-valued `NotIn`, `NOT(In(...))` and `NOT(NotIn(...))` no longer match rows where the column is NULL, consistent with `NotEqual`. A predicate under NOT on a column missing from an older data file no longer matches every row of that file; those rows match as a stored NULL would. Java's `Evaluator` still matches NULL for `notEq` and `notIn`, see [apache/iceberg#18701](https://github.com/apache/iceberg/issues/18701).
- **Commit rejections now match `table.ErrCommitRejected`.** SQL, Glue, Hive and Hadoop failures while preparing metadata, plus REST commit responses 400, 401, 403 and 404, leave transactions committable (after a REST 404, the next `Commit` fails when it reloads the table). Existing `errors.Is` matches keep working, but SQL, Glue, Hive and Hadoop rejection messages now start with `commit rejected: `, so code that matches error text may need updating.
- **Float comparisons against literals beyond the float32 range follow IEEE 754.** On a float32 column, `x < 1e100` no longer returns NaN, `+Inf` or NULL rows, and `NOT(x > 1e100)` no longer returns NULL rows. An infinite literal now binds to a float32 infinity, so `x = +Inf` matches `+Inf` rows. Java still folds these comparisons to always true or false, see [apache/iceberg#18700](https://github.com/apache/iceberg/issues/18700).

- [How to release](./how-to-release.md) - PMC/committer process for cutting an RC and publishing.
